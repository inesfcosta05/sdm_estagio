103	Normal	Este relatório apresenta o trabalho realizado no âmbito do projeto de estágio intitulado "Migração e Reestruturação de Plataforma de Gestão de Contactos", desenvolvido na empresa Celeuma Multimédia Lda entre fevereiro e junho de 2026.
104	Normal	
105	Normal	O projeto consistiu na modernização de uma plataforma existente baseada em WordPress, transformando-a numa aplicação web robusta e escalável utilizando um stack tecnológico moderno: React.js para frontend, Node.js/Express para backend, e MySQL para persistência de dados. A solução integra dados tanto da aplicação local como do WordPress, mantendo sincronização automática e garantindo compatibilidade com dados históricos.
106	Normal	
107	Normal	O trabalho foi organizado em fases: análise da arquitetura existente, levantamento de requisitos, design da nova arquitetura, implementação de backend e frontend, sincronização com WordPress, testes e deployment em ambiente local e de produção.
108	Normal	
109	Normal	A solução final implementa funcionalidades completas para gestão de fichas comerciais, clientes, páginas, perfis de utilizador, administração de acessos e relatórios, com interface intuitiva e consistente que privilegia a produtividade. O sistema implementa mecanismos avançados de adaptação dinâmica ao schema da base de dados, normalização de dados, sincronização incremental com WordPress e configuração por variáveis de ambiente.
110	Normal	
111	Normal	Os resultados demonstram uma melhoria significativa em termos de manutenibilidade, escalabilidade, coerência visual-funcional e experiência do utilizador comparativamente à solução anterior.
112	Normal	
113	Normal	Palavras-chave: Migração de plataformas, WordPress, React.js, Node.js, Arquitetura web, API REST, Sincronização de dados, Base de dados MySQL

120	Normal	This report presents the work carried out within the scope of the internship project titled "Migration and Restructuring of Contact Management Platform", developed at Celeuma Multimédia Lda between fevereiro e junho de 2026.
121	Normal	
122	Normal	The project consisted of modernizing an existing WordPress-based platform, transforming it into a robust and scalable web application using modern technology stack: React.js for frontend, Node.js/Express for backend, and MySQL for data persistence. The solution integrates data from both the local application and WordPress, maintaining automatic synchronization and ensuring compatibility with historical data.
123	Normal	
124	Normal	The work was organized in phases: analysis of existing architecture, requirements gathering, design of new architecture, backend and frontend implementation, WordPress synchronization, testing and deployment in local and production environments.
125	Normal	
126	Normal	The final solution implements complete features for managing commercial records, clients, pages, user profiles, access administration and reports, with an intuitive and consistent interface that prioritizes productivity. The system implements advanced mechanisms for dynamic adaptation to database schema, data normalization, incremental synchronization with WordPress and environment-based configuration.
127	Normal	
128	Normal	Results demonstrate significant improvement in terms of maintainability, scalability, visual-functional consistency and user experience compared to the previous solution.
129	Normal	
130	Normal	Key-words: Platform migration, WordPress, React.js, Node.js, Web architecture, REST API, Data synchronization, MySQL database

253	Body Text	Plataformas de gestão de contactos (também designadas CRM - Customer Relationship Management - ou sistemas de gestão de relacionamento com clientes) são ferramentas críticas para organizações que necessitam de gerir grandes volumes de informação sobre clientes, propostas, transações e comunicações.

259	Body Text	•  Fase 3 (Separação Frontend/Backend): API REST com frontend separado

267	Heading 2	Arquiteturas Web Separadas por Camadas
268	Body Text	A separação entre camadas (layered architecture) é um padrão amplamente aceito em engenharia de software que organiza a aplicação em:
269	Body Text	
270	Body Text	•  Camada de Apresentação (Frontend): Interface com o utilizador
271	Body Text	•  Camada de Lógica de Negócio (Backend): Processamento, validação, regras
272	Body Text	•  Camada de Persistência (Base de Dados): Armazenamento duradouro
273	Body Text	
274	Body Text	Vantagens:
275	Body Text	•  Manutenção independente de cada camada
276	Body Text	•  Reutilização da API por múltiplos clients
277	Body Text	•  Escalabilidade horizontal
278	Body Text	•  Facilita testes unitários e integração
279	Body Text	•  Flexibilidade tecnológica
280	Body Text	
281	Body Text	Esta arquitetura foi o modelo escolhido para o projeto, com React.js no frontend, Node.js/Express no backend e MySQL na camada de dados.
282	Heading 2	Wordpress como plataforma de Conteúdos
283	Body Text	WordPress é um Content Management System (CMS) muito popular, construído em PHP e MySQL. Inicialmente desenvolvido para blogging, evoluiu para plataforma robusta suportando:
284	Body Text	
285	Body Text	•  Extensão via plugins
286	Body Text	•  Tipos de conteúdo customizados
287	Body Text	•  REST API abrangente (desde versão 4.7)
288	Body Text	•  Ecossistema vasto de temas e extensões
289	Body Text	
290	Body Text	No contexto deste projeto, WordPress funciona como:
291	Body Text	•  Fonte de dados históricos: Dados de posts, clientes anteriores
292	Body Text	•  Sistema de referência: Validação de dados sincronizados
293	Body Text	•  Possível destino: Alguns dados criados localmente devem refletir em WordPress
294	Body Text	
295	Body Text	A integração com WordPress é complexa porque:
296	Body Text	•  Schema não é fixo (customizado com plugins)
297	Body Text	•  API tem limitações de autenticação e rate limiting
298	Body Text	•  Dados podem estar em formatos variados
299	Heading 2	APIs REST e Integração entre Sistemas
300	Body Text	REST (Representational State Transfer) é arquitetura para construir serviços web usando primitivos HTTP. Princípios:
301	Body Text	
302	Body Text	•  Identificadores de Recursos: URLs representam entidades (/fichas, /clientes)
303	Body Text	•  Operações Padrão: GET (ler), POST (criar), PUT (atualizar), DELETE (eliminar)
304	Body Text	•  Representações: Tipicamente JSON ou XML
305	Body Text	•  Stateless: Cada requisição é independente
306	Body Text	
307	Body Text	No projeto, a API REST expõe:
308	Body Text	•  Recursos principais: fichas, clientes, páginas, utilizadores
309	Body Text	•  Operações CRUD completas
310	Body Text	•  Filtros e paginação
311	Body Text	•  Autenticação via tokens
312	Body Text	
313	Body Text	A separação frontend/backend via REST API permite:
314	Body Text	•  Frontend focar em UI/UX
315	Body Text	•  Backend focar em lógica de negócio
316	Body Text	•  Fácil integração com outros sistemas
317	Heading 2	Frameworks Frontend Modernos
318	Body Text	React.js (desenvolvido pelo Facebook) é biblioteca JavaScript para construir interfaces:
319	Body Text	
320	Body Text	•  Componentes: Blocos reutilizáveis de UI
321	Body Text	•  Virtual DOM: Otimização de rendering
322	Body Text	•  JSX: Sintaxe que mistura JavaScript com HTML-like markup
323	Body Text	•  Hooks: Gerenciamento de estado e ciclo de vida
324	Body Text	•  Ecossistema: React Router (routing), Axios (HTTP), Bootstrap (styling)
325	Body Text	
326	Body Text	React foi escolhido porque:
327	Body Text	•  Comunidade grande e madura
328	Body Text	•  Ferramentas excelentes (Create React App)
329	Body Text	•  Componentes reutilizáveis simplificam desenvolvimento
330	Body Text	•  Performance satisfatória para aplicações administrativas
331	Body Text	•  Curva de aprendizagem razoável
332	Heading 2	Sincronização de Dados entre Sistemas
333	Body Text	
334	Body Text	Quando múltiplos sistemas armazenam dados relacionados, surge desafio de sincronização:
335	Body Text	
336	Body Text	•  Consistência Eventual: Dados sincronizam mas não instantaneamente
337	Body Text	•  Incrementais vs. Completas: Sincronizar apenas mudanças ou tudo
338	Body Text	•  Conflitos: Quando ambos os sistemas modificam o mesmo dado
339	Body Text	•  Performance: Sincronização não deve bloquear operações normais
340	Body Text	
341	Body Text	Estratégias comuns:
342	Body Text	•  Polling: Sistema verifica periodicamente por mudanças
343	Body Text	•  Webhooks: Sistema receptor é notificado de mudanças
344	Body Text	•  ETL: Extração, transformação, carregamento de dados

1904	Heading 2	Sincronização com Estados Inesperados
1905	Body Text	
1906	Body Text	Problema: WordPress API às vezes retorna dados incompletos ou inesperados (HTTP 400, timeout).
1907	Body Text	
1908	Body Text	Erros observados:
1909	Body Text	400 Bad Request - campos faltam
1910	Body Text	401 Unauthorized - credenciais expiradas  
1911	Body Text	429 Too Many Requests - rate limiting
1912	Body Text	504 Gateway Timeout - WordPress offline
1913	Body Text	
1914	Body Text	Solução Implementada:
1915	Body Text	
1916	Body Text	async function syncWithRetry(maxRetries = 3) {
1917	Body Text	  for (let attempt = 1; attempt <= maxRetries; attempt++) {
1918	Body Text	    try {
1919	Body Text	      const fichas = await wpClient.get('/wp-json/wp/v2/fichas');
1920	Body Text	      return fichas.data;
1921	Body Text	    } catch (error) {
1922	Body Text	      console.warn(Tentativa ${attempt} falhou:, error.message);
1923	Body Text	      
1924	Body Text	      if (error.response?.status === 401) {
1925	Body Text	        console.error('Credenciais WordPress inválidas - sincronização desativada');
1926	Body Text	        return [];
1927	Body Text	      }
1928	Body Text	      
1929	Body Text	      if (attempt < maxRetries) {
1930	Body Text	        const waitTime = Math.pow(2, attempt) * 1000; // Exponential backoff
1931	Body Text	        console.log(Aguardando ${waitTime}ms antes de repetir...);
1932	Body Text	        await new Promise(r => setTimeout(r, waitTime));
1933	Body Text	      }
1934	Body Text	    }
1935	Body Text	  }
1936	Body Text	  
1937	Body Text	  console.error('Sincronização falhou após todas as tentativas');
1938	Body Text	  return [];
1939	Body Text	}
1940	Body Text	
1941	Body Text	Resultado: Sistema é resiliente a falhas temporárias de WordPress.
